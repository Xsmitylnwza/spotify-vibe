# P5-U1 — reliable desktop updates

Implemented decision #46 desktop/release contract; no commit, tag, push, release, or owner-profile install.

- `electron/updates.mjs`: shared production state controller exposes `{currentVersion, state, availableVersion, percent, error}`. States are idle/checking/available/downloading/downloaded/error. Explicit downloads only (`autoDownload=false`), no automatic install on quit. Serial operations, check deadline, visible failures/retry, and scheduled checks preserve an active download or downloaded installer.
- `electron/main.js`: snapshot/actions use the existing sender/main-frame/origin-guarded IPC. First check remains 20 seconds after shell startup, then every 6 hours. Restart delegates to existing bounded cleanup/install-failure fallback, unchanged in `electron/lifecycle.mjs`.
- `electron/preload.cjs`: adds `download()` and `restartToUpdate()`; retains `downloadUpdate()` / `quitAndInstall()` aliases and legacy snapshot fields (`available`, `checking`, `downloading`, `downloaded`, `progress`) for the current banner. Renderer/sidebar changes belong to the renderer lane.
- `.github/workflows/release.yml`: runs `electron/release-version.mjs` before npm ci/build/release; rejects malformed/mismatched `vX.Y.Z` tags and either stale lockfile version. Package stays 1.0.7.
- Ran `npm install --package-lock-only --ignore-scripts --no-audit --no-fund`: both lockfile versions now 1.0.7 and updater dependency classification matches package.json. Compared every dependency version/resolved/integrity with HEAD: zero changes, zero added packages.

Validation:

- Focused Electron suite: **31 passed, 0 failed** (final run; initial run before extra host/preload coverage was 29/29).
- **npm test run once: 194 passed, 0 failed**, no skipped/cancelled tests; 13.54 seconds. Shared checkout includes contemporaneous renderer-worker changes; they were neither edited nor reverted by this worker.
- `scripts/tests/electron-update-feed.test.mjs` serves localhost `latest.yml` metadata for fake 1.0.7 then 1.0.8 and SHA512/size-described EXE artifacts. Real `electron-updater` 6.8.9 `NsisUpdater` / generic provider compares versions, performs the download, validates SHA512, caches bytes, emits progress, and reaches **available -> downloading -> downloaded**. Checks make zero artifact requests before the explicit download. Downloaded bytes match the served artifact; a subsequent scheduled check preserves the installer.
- Feed test uses an isolated temp app/cache adapter and Node HTTP request transport with electron-updater's download implementation; it does **not** launch Electron or execute the fake EXE. `restartToUpdate()` reaches a `quitAndInstall(false, true)` spy after cleanup. Separate actual-main VM host tests verify guarded IPC, 20-second/6-hour scheduling, explicit actions, cleanup, successful exit, and installer error/hang fallback. Preload actions are evaluated, not source-string matched.
- Release guard accepts matching versions and rejects malformed/mismatched tags plus each stale lock version. Scoped `git diff --check` passed. Feed server/connections and temporary cache were cleaned; no companion/Electron processes were launched by the feed test.

Packaged install boundary remains manual: no vA/vB installer build or installed upgrade round-trip was performed. `WindowsSandbox.exe` was unavailable and no disposable Windows install environment was established; NSIS uses installation registry/shortcut state outside `/D=<temp>`, so a temp directory alone would not isolate the owner's installed app/profile. Provisioning that environment was not feasible within this task's approximately 20-minute optional gate.

Manual gate: in a disposable Windows account/VM, build vA and vB with publishing disabled, install vA into a temp directory, use isolated config/secrets/userData with autostart disabled, point its updater at a localhost generic vB feed, verify the sidebar's new-version/progress/restart states, click Restart, complete NSIS, and confirm the relaunched executable reports vB and preserves config. Native Electron HTTP transport, real installer/signature execution, process replacement, and installed-version persistence are unverified until that gate passes. Production feed/provider remains GitHub; the test does not change it.
