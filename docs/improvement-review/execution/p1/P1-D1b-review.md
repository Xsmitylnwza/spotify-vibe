## Remaining finding

### R3b — Major: shutdown abandons cleanup of a late handle already in hand

**Location:** `electron/lifecycle.mjs:93`, `electron/lifecycle.mjs:97`, `electron/lifecycle.mjs:112`, `electron/lifecycle.mjs:114`; host wiring `electron/main.js:279` and `electron/main.js:282`.

**Concrete scenario:** OS Quit arrives while startup is pending. `startup.stop()` marks startup cancelled and begins its one-second wait. Before that deadline, startup returns an owned handle whose `stop()` takes longer than the remaining wait, but remains within the server's bounded-stop contract. The raw continuation enters the cancelled branch and calls `stopOnce(value)` without assigning `handle`. At the one-second deadline, the wait ends; `if (handle)` is false, so main destroys the tray and calls native quit while this cleanup is still running. Terminating Electron prevents its in-process continuation from completing; helper/RPC cleanup can be cut off.

**Evidence — reproduced at the actual-main boundary:** Loaded the real main and helpers in the existing VM host fixture, using an in-memory fixture extension only. Emitted OS Quit, resolved startup to an owned handle before firing the one-second timer, and held that handle's stop promise. Result at native quit: `quit=1, stops=1, stopComplete=false, windows=0`. Releasing stop afterward completed it in the fake host, which intentionally does not terminate Node. Calling stop once therefore passes the existing tests while cleanup-before-exit fails. The ordering defect is reproduced; an orphaned real Windows helper is a consequence hypothesis, not a native reproduction.

**Smallest fix:** Retain every obtained owned handle before branching on cancellation/expiry, or retain its cleanup promise as lifecycle state. After the bounded wait for *obtaining* a handle, await the existing bounded `stopOnce` for any handle/cleanup already known before final quit. Preserve WeakMap idempotence. Add an actual-main test resolving startup during the one-second window with a deferred stop, asserting zero quit until cleanup completes and then exactly one quit. Handles arriving after actual process exit additionally require a startup cancellation/resource-ownership contract; a JavaScript continuation alone cannot guarantee post-exit cleanup.
