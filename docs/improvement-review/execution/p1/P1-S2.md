## Limits and risks

- **Unverified:** real Discord delivery, packaged Electron/manual Quit, real PowerShell cancellation timing, and physical disk-full/power-loss crash recovery. Injected boundary failures and fake RPC/child adapters establish the code behavior, not those external outcomes.
- **Inferred:** successful replacement is atomic on the supported local filesystem. Temp and newly created backup file contents are explicitly synced before replacement; directory metadata/power-loss durability was not certified.
- **Verified behavior / tradeoff:** Windows rename EPERM/EEXIST now fails safely and retains the old destination instead of deleting it to retry. The caller receives an error and may retry once the external lock clears.
- **Verified scope boundary:** mapping-route activation behavior remains for P1-S1/C1 to change; no per-file lease, legacy-writer handoff, profile descriptor or multi-tab 409 mechanism was introduced. Renderer and Electron files were not edited by this worker.
- **Inferred limitation:** process-local queues protect this companion's updates, not writes from other processes. Global installed-app cache/single-flight remains the existing design; profile-descriptor/isolation infrastructure is Parked.
- **Remaining:** coordinator's independent implementation review and subsequent server tasks; no release acceptance is claimed.
