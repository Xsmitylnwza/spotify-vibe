## P1-D1c

Fixed re-review Major R3b in `electron/lifecycle.mjs` only; extended `scripts/tests/electron-host.test.mjs` and appended this report. Main Quit wiring, IPC/navigation security, updater handling, server and renderer files were unchanged by this dispatch. No dependencies, commits, packaging or native Electron run.

- **Change:** `electron/lifecycle.mjs:95` retains each owned startup handle before the cancelled/expired branch. Shutdown therefore awaits the same WeakMap-cached stop promise already started for a late handle, rather than returning at the startup-wait deadline while cleanup is pending. One stop per handle and the no-window-after-shutdown behavior remain intact.
- **Bound:** `electron/lifecycle.mjs:82` adds a four-second outer cleanup deadline; `electron/lifecycle.mjs:118` awaits known-handle cleanup with that deadline after the existing one-second startup wait. The maximum asynchronous wait before native Quit/tray cleanup is **five seconds** (one second obtaining a handle plus up to four seconds awaiting cleanup), subject to event-loop scheduling. The server's existing bounded stop should settle sooner; an overrun reports `STUDIO_STOP_TIMEOUT` through the existing shutdown error publisher and still permits Quit. No server edit was needed.
- **Verified regression:** actual-main fixture at `scripts/tests/electron-host.test.mjs:104` emits OS Quit, resolves startup before the one-second timer, and holds stop pending. At that timer, it requires `quit=0, stops=1, stopComplete=false, windows=0`; releasing cleanup then requires exactly one native quit and one completed stop. The timeout variant holds cleanup beyond the four-second outer bound, verifies native Quit proceeds once, then releases the underlying stop and invokes later HTTP-style `onQuit` without a second stop/quit.
