# P4-2 — Release a clean Studio renderer while hidden

## Change and boundaries

[Verified source/tests] `electron/tray-window.mjs:35` owns one 30-second grace/retry timer while a hidden window exists. A clean, owned Studio window is destroyed; dirty, in-flight, unknown, failed or timed-out probes retain it. Showing, replacing or quitting invalidates pending release decisions. No renderer files, detector/server files, dependencies, startup configuration or commits were changed.

[Verified source/tests] `electron/main.js:81` captures each window's identity, wires hide/show, avoids clearing a newer window from an older closed event, and guards maximize notifications. `electron/main.js:103` routes tray Open, tray clicks, second-instance (`:40`), activate (`:308`) and the existing open IPC through recreation. The last owned URL hash is restored on the same owned server URL. `electron/main.js:281` stops release scheduling before companion shutdown. Hidden startup schedules the same release (`:351`). Owned-server startup, privileged IPC guard (`:228`), locked navigation and bounded idempotent shutdown remain intact; the existing lifecycle/security modules were not changed.

[Verified source/tests] Update broadcasts (`electron/main.js:166`, existing `broadcastUpdateState`) accept zero live windows and tray menus still refresh. The recreated renderer retrieves current update state through the existing IPC. This project has no native Electron Notification/displayBalloon path; packaged update feed/download/install and real notification clicks were not exercised live.

## Read-only save-state proof

The probe is `readStudioSaveState`, `electron/tray-window.mjs:5`, executed in the page main world with `webContents.executeJavaScript`. Studio uses a classic script, so its top-level lexical bindings are readable without adding renderer exports. The probe reads flags/config only; it never calls save/flush APIs, mutates inputs or copies secret field contents. Its only request is a read-only, uncached GET `/api/config`.

* `document.readyState`, `config` and `_lastSave.state`: initialization must complete and the semantic state must be `saved`. `setSaveState` updates `_lastSave` and `#savebar.dataset.state` together (`scripts/discord-presence-studio.html:1453`); translated display text is not used. Dirty, warning/error and missing state retain the window.
* `saveButton.disabled`, `saveSettingsButton.disabled`, `applyBusy`, and `saveChain`: saves set the busy flag before queueing (`:2797`) and serialize onto `saveChain` (`:2827`). The probe awaits the current chain, then checks identity and flags again after GET. An earlier successful operation cannot hide a still-pending queued Scene save. Main limits the entire probe to 2 seconds; timeout means unknown and retain.
* `settingsFormDirty`: protects unsaved API-key settings without reading their values (`:1219`).
* In-memory `config.scenes` and `config.slots` must exactly match the persisted public GET response. `mappingDraft` must also match confirmed `config.appMappings`, so an unconfirmed pairing draft retains the renderer.
* `formScene()` is compared field-by-field with `currentScene()` (`:1811`, `:1838`). This protects typed DOM values even when a stale save indicator says saved. `timerMode`/`timerMinutes` are excluded because `formScene` hardcodes them and no timer controls exist; legacy defaults use `elapsed` and are not unsaved edits. Other unknown/mismatched fields fail closed.

[Verified] Actual isolated renderer probes returned `clean` in five recreation cycles. [Verified injected tests] Dirty form values, failed save, settings draft, active/queued saves and missing bindings retain state. [Inferred limitation] This is coupled to the current classic-script contract; future renderer refactoring must update the probe. Missing bindings fail closed. A renderer that already discarded a draft before probing is outside this change's protection. Dirty/unknown hidden windows intentionally keep their memory and retry once per 30 seconds.
