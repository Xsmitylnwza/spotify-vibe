## Limits and risks

- Serial measurements on a busy shared workstation establish observed differences, not a controlled attribution of every CPU/WS delta. Machine CPU is retained per CSV; the companion tree excludes other workers, sampler and test apps. Final-source tests/fault probes run outside the retained full capture windows; machine load from other workers remains uncontrolled.
- WS is the sum of process working sets, double-counting shared pages; short-lived between-sample processes and exit-tail CPU are underobserved, as in the baseline. Independent scheduler/RPC savings are behaviorally verified, not isolated performance measurements.
- The process cache retains one handle per readable running PID and releases exited identities each scan; executable icon/name caches retain prior executable metadata for the helper lifetime, as the original icon cache did. Access restrictions and very short-lived processes remain detection limits. Current parity is verified; general elevated-app coverage is unverified.
- Focus timing measures API snapshot/desired Scene, not Discord delivery; real RPC was not configured. Hermetic tests verify RPC no-op/transition behavior. Latencies include HTTP polling and the native activation procedure and are conservative upper bounds from immediately before AppActivate, not exact WinEvent timestamps.
- Approved Codex artwork/path logic is source-verified; a live Codex-version-upgrade scenario was not exercised. Existing version-normalized mapping tests pass.
- Coordinator review remains required; this implementer report is not final owner/reviewer acceptance.

Concurrent renderer/Electron lane source drift was observed between captures/current checkout; the summarizer verifies every captured source against its snapshot, and current hashes only for this task's detector/server/app-policy files. Electron is not launched and renderer is not opened in these captures; those other-lane changes are preserved.
