## P2-R1b — updater behaviours restored + endpoint re-check
The P2-R1 port had flattened the updater (no snapshot guard, no request serialization, no error-key relocalization). `scripts/discord-presence-studio.html` now has one update model (`UPD`: `rev`, `busy`, `localError` as a key, `downloaded` flag) feeding the banner, the sidebar Update button and the Settings → Updates card (status, offered action, manual check).
- Restored behaviours (each with a TH+EN behavioural test in `scripts/tests/renderer-updates.test.mjs`, 17 tests, run against the real desktop-shell block with a fake preload bridge): (1) a late `getUpdateState` snapshot is dropped if a newer push arrived; (2) pushed errors override available/downloaded copy and offer Download/Restart/Check recovery; (3) banner, sidebar and Settings share one in-flight request (no double download/restart/check); (4) `download()`/`quitAndInstall()` resolving `{ok:false}` or throwing shows a visible failure and stays retryable; (5) language switch re-localizes banner, sidebar and Settings text; (6) idle is not claimed "latest" before a check; checking disables controls; check failure and "unavailable" are shown and recover on a good check; (7) dismiss hides one version, a manual recheck restores banner + action (Settings stays actionable throughout).
- Launch at startup: toggle exists in Settings (desktop only, `launchRowHtml`), reads `getOpenAtLogin`, writes `setOpenAtLogin`, a failed change toasts and is not shown as applied; covered by a test. Verified in headless Chrome with an injected fake `window.vibeStudio` (toggle present, checked).
- Endpoints re-checked against the running isolated server (headless Chrome + curl): `POST /api/reconnect` returns 200 `{ok:false,runtime}` with Discord disabled (UI reports "still not connected" + next retry); `publicIcon` is present on `/api/apps` and `/api/installed-apps` (Claude, Access… have https icons) and the large-image App icon tab offers "Use" only for those, which then sets the image to that URL; `scenes[].enabled` toggles from the Scenes list persist (`morning:false` then back to true).
- Not verified: inside real Electron, and Reconnect against a live Discord (success path).
