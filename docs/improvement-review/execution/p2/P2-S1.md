## Changes (verified in source and behavioral tests)

- `scripts/studio-server.mjs`: `POST /api/reconnect` cancels backoff and awaits the existing RPC connect path. Requests share one authoritative connection promise, including startup login; failure returns HTTP 200 with `ok:false` and the runtime error. A connected client is torn down before an explicit fresh attempt. Settings-driven identity changes invalidate an old pending attempt; its late result cannot overwrite a replacement or clear the replacement promise.
- Reconnect accepts the server's actual `127.0.0.1:<port>` Host and an absent or exact matching Origin. Absolute request URLs cannot bypass Host checking. Existing source had URL/Host syntax validation but no reusable local-origin guard; this route adds explicit checks without changing other route contracts.
- Both app catalog routes return fresh app objects with `publicIcon:packedAppIcon(app)`, preserving every other field. Installed-app catalog read/refresh adapters are injectable for boundary tests. `scripts/app-icon-pack.mjs` changes only the default ref constant to `main`.
- `scripts/presence-config.mjs`: `validateScene` retains boolean `enabled`, defaults absent values to true, and rejects non-booleans. HTTP config save/read and persisted JSON round-trip the field; rejected input leaves disk unchanged.
- `scripts/app-presence.mjs`: both app selection helpers accept optional Scene data and exclude mappings to `enabled:false` Scenes. The server supplies its Scenes, so recent disabled mappings fall through to another running enabled mapping.
- **Pin policy:** explicit manual override is evaluated before automatic app selection and may show a disabled Scene. Disabled means excluded from automatic app selection; explicit owner pin behavior remains authoritative. Legacy schedule behavior is unchanged.
- New tests: `scripts/tests/studio-p2-endpoints.test.mjs` (9 tests) exercise real localhost HTTP with fake RPC, watcher and installed-app catalog/refresh adapters, plus helper selection assertions.
