# Spotify Vibe — Automatic Character Presence

วันที่ตรวจ: 2026-09-05 · สถานะ: ข้อเสนอเพื่อคุยต่อ ยังไม่ใช่สเปกที่ผู้ใช้ยืนยัน

## เป้าหมาย

ทำให้คนที่พบกิจกรรมของเจ้าของบน Discord จำบุคลิกได้จากตัวละครและข้อความที่เปลี่ยนตามชีวิตจริง โดยเจ้าของไม่ต้องเปิด Studio มาแต่ง Scene ทุกวัน ความสำเร็จมีทั้งความอัตโนมัติ ความจำได้ และการมองเห็นจริงบน Discord

## ช่องว่างของประสบการณ์

1. Auto ตามเวลาไม่เท่ากับ auto ตามชีวิต: เวลา 23:00 อาจขึ้นนอนทั้งที่ยังเล่นเกม
2. การแต่งเป็นราย Scene ทำให้ต้องคุมความสอดคล้องของรูปและข้อความเอง
3. ไม่มีความจำข้ามกิจกรรม จึงรู้สึกเป็นสไลด์เปลี่ยนภาพ
4. Studio ให้ความสำคัญกับการกรอก มากกว่าการบอกว่าตอนนี้เลือกอะไรเพราะอะไร
5. Auto ไม่ได้เพิ่มพื้นที่แสดงใน Discord; ต้องพิสูจน์ความเห็นชัดและความจำได้จากฝั่งคนอื่นก่อนลงทุนภาพจำนวนมาก

## ประสบการณ์ที่เสนอ

ครั้งแรก: เลือกชุดตัวละคร → จัดแอปที่ใช้เข้ากลุ่ม → ดูตัวอย่างลำดับหนึ่งวัน → เปิด Auto

วันปกติ: เปิดเครื่องแล้วใช้งานตามปกติ ตัวละครเปลี่ยนตามกิจกรรมที่ตรวจได้ เปิด Studio เฉพาะเมื่อต้องการแต่งหรือแก้การจับกิจกรรม

หน้าแรก Studio แสดงตัวละครปัจจุบัน, การ์ดที่ระบบกำลังส่ง, เหตุผลที่เลือก เช่น “Coding เพราะ VS Code ใช้งานต่อเนื่อง”, สถานะส่งสำเร็จ/ขาดการเชื่อมต่อ และปุ่มพัก Auto / ใช้โหมดนี้ชั่วคราว / กลับ Auto

หน้า Character ใช้ชุดภาพและคลังข้อความร่วมกันทุกโหมด หน้า Automation ให้แก้การจับคู่แอปกับโหมด ส่วน Scene editor เดิมอยู่ใน Advanced และยังใช้ได้

## ระบบ Auto ที่เสนอ

- รับสัญญาณชื่อ executable ของแอป foreground ที่เจ้าของเลือกให้ใช้, idle และ lock จาก Windows; ไม่ต้องอ่านชื่อเอกสาร ข้อความหน้าต่าง หรือเนื้อหาจอเพื่อบอกโหมดพื้นฐาน
- เปิดโปรแกรมค้างไว้ไม่ถือว่ากำลังใช้; แยกแอป foreground กับแอป background
- ค่าเริ่มต้นทดลอง: foreground คงที่ 20 วินาทีก่อนเปลี่ยนโหมด, เก็บโหมดเดิม 60 วินาทีสำหรับการ Alt-Tab สั้น ๆ, ห่างจาก input 5 นาทีจึงพิจารณา Away ค่านี้ยังต้องลองใช้จริง
- idle อย่างเดียวไม่พิสูจน์ว่าไม่อยู่ เพราะอาจดูวิดีโอ; ให้กิจกรรมสื่อที่ตรวจได้ยับยั้ง Away หรือให้เลือกข้อยกเว้น
- ถ้าตรวจแอปไม่ได้ ให้ใช้ daily slot เดิมเป็น fallback แบบไม่อ้างว่ารู้กิจกรรมจริง; ข้อความกลางคืนใช้ “After hours” แทนการฟันธงว่านอน
- Override เลือก 30 นาที / 1 ชั่วโมง / จนกว่าจะยกเลิก โดยไม่ต้องมี schedule
- ลำดับเสนอ: Clear/ซ่อน → lock policy → manual override → กิจกรรมที่ยืนยัน → Away → schedule fallback; การให้เกมแสดงเองต้องเป็น policy แยกที่ทดสอบกับเกมจริง
- เก็บ startedAt ของช่วงกิจกรรม; เปลี่ยนคำหรือเครื่องแต่งกายไม่รีเซ็ต timer
- ส่งเฉพาะเมื่อผลลัพธ์เปลี่ยน รวมการส่งและ backoff; ไม่ส่งทุกครั้งที่ตรวจแอป
- ตรวจล้มเหลวต้องเห็นเหตุผลใน Studio และหยุดใช้สัญญาณเก่าหลังพ้นช่วงผ่อนผัน

## คาแรคเตอร์ที่เสนอ (รอเลือกทิศทาง)

แนะนำตัวเดียว หลายสภาพ: silhouette/หน้า/สีหลักคงที่ เปลี่ยนท่า อุปกรณ์ และอาการตามกิจกรรม ใช้ภาพที่อ่านออกในขนาดเล็ก ไม่มีข้อความเล็กฝังในรูป

เริ่ม 6 สภาพ: Idle, Coding, Gaming, Media, Away, Late-night โดย Late-night อาจเป็นชั้นตกแต่งทับ Coding/Gaming แทนแย่งโหมดหลัก

แยก 3 ชั้น:

1. กิจกรรมที่ตรวจได้ — เช่น Coding
2. สภาพสะสมจากระยะเวลา/การเปลี่ยนโหมด — เช่น ควันออกหัว เป็นเรื่องแต่งที่อิงการใช้งาน ไม่ใช่ข้อสรุปสุขภาพหรืออารมณ์
3. การนำเสนอ — ภาพ ข้อความกวน และรายละเอียดสั้น

ตัวอย่าง: ใช้ editor นาน → หุ่นมีควัน → เปิดเกม → ถือประแจเข้าเกม → กลับ editor → ยังใส่หมวกเกมชั่วครู่ เป็นความจำจากการเปลี่ยนแอปที่ตรวจได้ ไม่ต้องรู้ผลแพ้ชนะ

เก็บประวัติขั้นต่ำเป็น mode, enteredAt, previousMode, decorationExpiry; การรีสตาร์ตหรือเปลี่ยนวันต้องหมดอายุสภาพเก่าอย่างชัดเจน

ภาพเริ่มต้นควรเป็นชุดที่เตรียมล่วงหน้าเพื่อคุมตัวตนและความเร็ว Local file ใช้เป็นภาพ Discord โดยตรงไม่ได้ตามเส้นทางปัจจุบัน ต้องกำหนด asset key/HTTPS hosting และพิสูจน์ภาพเคลื่อนไหวใน client จริงก่อนเลือก pipeline; ยังไม่มีการอัปโหลดหรือสร้างภาพ

AI ใช้ช่วยออกแบบภาพและคลังประโยคล่วงหน้าได้ ส่วนการเรียกโมเดลขณะใช้งานเป็นทางเลือกภายหลัง ไม่จำเป็นต่อ Auto รุ่นแรก

## ขอบเขตที่ต้องพิสูจน์ก่อนสร้างเต็ม

- ให้เพื่อนหรือบัญชีผู้ดูอีกฝั่งตรวจ member list, profile/activity card และ desktop/mobile: ตรงไหนมองเห็นจริง ภาพเล็กและภาพเคลื่อนไหวอ่านออกหรือไม่
- เกมที่มี Presence ของตัวเองกับ custom Presence อยู่ร่วมกันอย่างไร; ถ้าแย่งพื้นที่ ให้ตัวเลือก “ปล่อยเกมแสดงเอง” และทดสอบว่าล้าง activity ของ companion แล้วกลับได้
- Detector บน Windows เชื่อถือได้แค่ไหนในแอปที่ผู้ใช้ใช้จริง รวมเกมที่ใช้ controller และแอปที่เปิด media ทิ้งไว้
- ภาพชุดเดียวเพียงพอให้ผู้ดูจำว่าเป็นเจ้าของหรือยัง ก่อนเพิ่มระบบความจำซับซ้อน

## ลำดับพัฒนาเสนอ

1. Auto แบบอธิบายได้: detector → resolver → Scene เดิม พร้อม simulation ที่ไม่ส่ง Discord และการคืน fallback; ลองวันใช้งานจริงก่อน
2. Character pack: ชุดภาพ/ข้อความหนึ่งตัว ครอบคลุมโหมดหลัก ใช้ผลลัพธ์จาก Auto เดิม
3. Continuity: สภาพตกค้างข้ามโหมดพร้อม expiry และตัวเลือกปรับความปั่น

เกณฑ์รับงานเสนอ: ใช้งานวันปกติโดยไม่ต้องเปิด Studio เพื่อเปลี่ยนโหมด, Alt-Tab สั้นไม่ทำให้กระพริบเปลี่ยน, เปิดหลายแอปเลือกตรงกับกฎที่อธิบายได้, เปลี่ยนภาพไม่รีเซ็ตเวลา, reconnect คืนผลล่าสุด, ผู้ดูอีกฝั่งเห็นและจำตัวละครได้จริง

## ความต่อเนื่องกับของเดิม

นำ scheduler, Scene validation, RPC queue/reconnect, persistence, autostart และ editor เดิมกลับมาใช้ เพิ่ม detector/resolver/character renderer เป็นส่วนแยก Migration ต้องรักษา Scene และ schedule เดิม พร้อมกลับ schedule-only ได้

ADR 0004 และเอกสาร scope เดิมตั้งใจจำกัดผลิตภัณฑ์ไว้ที่ scheduled Presence; ผู้ใช้กำลังขอขยาย scope นี้ ข้อเสนอนี้ยังไม่เขียนทับการตัดสินใจเก่าจนกว่าจะตกลงแนวทางใหม่
