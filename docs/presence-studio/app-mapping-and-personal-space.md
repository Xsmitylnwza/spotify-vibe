# App Mapping และพื้นที่โชว์ตัวตน

อัปเดตจากคำชี้นำผู้ใช้ 2026-09-05 — ใช้แทนข้อเสนอเรื่อง lore/ห้องของมาสคอตในเอกสารก่อนหน้า

## ยืนยันจากผู้ใช้

- เจ้าของเป็นคนกำหนดว่าใช้แอปใดแล้วให้ Discord แสดงอะไร
- Studio ต้องช่วยให้เลือกแอปในเครื่องได้ง่าย ไม่บังคับให้จำชื่อ process หรือพิมพ์ path
- ระบบนำคู่ที่เจ้าของตั้งไว้มาใช้ตามกิจกรรม ไม่เลือกบุคลิกหรือเขียน status ให้เองโดยพลการ
- หน้าจากลิงก์ต้องโชว์ความเป็นเจ้าของ รสนิยม และสิ่งที่สร้าง ไม่เล่าประวัติหรือจักรวาลของ GIF/มาสคอต
- ทิศทางภาพรวม: อินดี้ แปลก เท่ มีอะไรให้สำรวจ; หน้าพิกเซลเป็นลายเซ็นภาพของเจ้าของ

## Studio ที่เสนอ

เริ่มจากรายการแอป → เลือกแอป → กำหนดการ์ด Discord ของแอปนั้น → บันทึกคู่ → ระบบสลับให้เมื่อใช้งาน

ตัวเลือกค้นหาแอปเสนอ: แอปที่เปิดอยู่เป็นรายการหลัก พร้อมค้นหาแอปที่ติดตั้ง และเลือกไฟล์โปรแกรมเองเป็น fallback การตรวจแอปเป็นความสามารถที่จะเพิ่ม ไม่ใช่สิ่งที่โค้ดเดิมทำได้แล้ว

ในรายการหนึ่งแถวแสดง icon/name ของแอป, ภาพย่อการ์ดที่จับคู่, enabled/disabled และปุ่มแก้ไข เมื่อแอปนั้นกำลังควบคุม Presence ให้เห็นป้ายว่ากำลังใช้งาน

หนึ่งแอปกำหนดภาพ GIF, badge, ข้อความ, timer และปลายทางลิงก์ของตนได้ ใช้การ์ดเดิมร่วมกันหรือทำสำเนาเพื่อแก้เฉพาะแอปได้ รายละเอียดระดับอิสระของ editor ยังเปิดให้คุย

ค่าพฤติกรรมที่แนะนำแต่ยังต้องตกลง: ถ้าเปิดหลายแอปให้ใช้ตัวที่กำลังใช้งานด้านหน้าและมีช่วงผ่อนผันสำหรับ Alt-Tab; แอปที่ไม่ได้จับคู่ใช้การ์ดกลาง; pin การ์ดชั่วคราวได้; เกมที่อยู่ background/การดูสื่อเป็นข้อยกเว้นที่จะคุยแยก

## พื้นที่ public ที่เสนอ: โต๊ะทดลองส่วนตัว

เปิดหน้าเดียวแล้วเห็นรสนิยมและงานของเจ้าของ ผ่านองค์ประกอบที่เลือกเอง:

- ของที่กำลังสร้าง: งานหนึ่งชิ้นที่อยากโชว์ มี demo/media ที่กดเล่นหรือดูได้
- ชั้นของทดลอง: ชิ้นงานเล็ก ๆ และของแปลกที่ทำไว้ กดแล้วพบของจริง
- รสนิยม: ภาพ สี เสียง/ลิงก์เพลง หรือสิ่งที่เจ้าของเลือกจัดวางเอง ไม่สมมติว่ามีการอ่านข้อมูลแอปเหล่านั้นอัตโนมัติ
- รายละเอียดเกี่ยวกับเจ้าของ: ข้อความสั้นและทางไป GitHub/พอร์ตเต็ม
- หน้าพิกเซล: ใช้เป็นภาพประจำตัวหรือองค์ประกอบหนึ่งในหน้า ไม่เป็นหัวข้อชีวประวัติมาสคอต

การนำเสนอเสนอเป็นโต๊ะ/หน้าต่าง/วัตถุแบบอินดี้ที่มีองค์ประกอบน้อยและชัด แต่ยังไม่ล็อก layout, 2D/3D, framework หรือชุดสี

ลิงก์หลักเป็นพื้นที่ตัวตนเดียวกันที่ผู้ชมจำได้ แต่เลือก deep-link เป็นรายแอปได้ เช่น editor → งานที่กำลังโชว์, โปรแกรมฟังเพลง → มุมเพลงที่เลือกไว้, เกม → มุมเกม/ของเล่น การเชื่อม context เป็นค่าที่เจ้าของกำหนด ไม่ใช่ระบบเดาประวัติส่วนตัว

## สิ่งที่แทนที่จากข้อเสนอเดิม

- ยกเลิก lore/ประวัติของตัวละครและตู้รวมร่างจากแกนหน้า public
- การโต้ตอบกับมาสคอตและความจำข้ามกิจกรรมไม่ใช่แกนที่จำเป็นของเวอร์ชันนี้
- ให้ app mapping เป็นศูนย์กลางของ Studio แทนเริ่มจากชุดโหมดสำเร็จที่ agent เลือกให้
- คง Auto, original pixel GIF, Discord clickable fields และพื้นฐาน companion ที่ใช้ได้ทุกวัน
